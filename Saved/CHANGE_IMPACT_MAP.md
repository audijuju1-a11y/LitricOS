# Change Impact Map

Use this as a starting dependency map; search code and docs before changing a public contract. It is derived from Cargo edges, crate responsibilities, tests and ADRs and does not replace a fresh `rg`/build check.

| Change area | Likely source owners | Contract/configuration impacts | Required verification targets |
|---|---|---|---|
| App identity, ABI, errors, handles | `litric-core` (`id.rs`, `version.rs`, `error.rs`, `handle.rs`) | `litric-caps`, manifest/storage, system protocols, ABI/security doc, package declarations, every consumer | core tests, dependent crate tests, manifest/IPC compatibility and ABI review |
| Capability IDs/scopes/live consent | `litric-caps/src/capability.rs` | `litric-manifest`, `litric-storage`, `litric-sysd` provider grants, protocol tokens, shell prompts, `docs/SEC-01-capabilities.md`, tests | cap scope/consent/revocation tests; provider tests; wire/document table sync; security review |
| Grants/audit/persistence/authentication | `litric-caps/src/lib.rs`, `litric-sysd/src/state.rs`, server | daemon identity, peer credential/cgroup policy, persistence location, units/socket permissions, audit UI and recovery | forged identity/unauthorized socket tests, restart durability, revocation/live-consent integration, secrets review |
| Storage URI/layout/path policy | `litric-storage/src/lib.rs`, `litric-files/src/path.rs` and `ops.rs`, shell `fsbridge.rs` | capability names/scopes, logical path semantics, LFP/1 values, trash/archive metadata, root directory and service confinement | URI/property tests, symlink/TOCTOU tests, cross-app denial, filesystem crash and disk-full tests |

## Cross-cutting rule

For a behavior change, follow the complete path: caller/UI → typed model → protocol/IPC → service identity/policy → operating-system effect → persistence/recovery → tests and evidence. If any link is only planned or absent, reduce the user-facing claim rather than presenting a state-only model as an executed action.
